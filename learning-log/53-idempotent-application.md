# Q2. The ON CONFLICT DO NOTHING clause means that on a retry, the INSERT produces no RETURNING rows, and the code falls back to a SELECT to retrieve the existing row. This means a retry always costs one extra round-trip (INSERT → SELECT) compared to a first submission (INSERT → return). Propose a way to eliminate the extra SELECT on retry. Write the SQL.


xtra SELECT khatam karne ka tareeqa: DO UPDATE no-op trick use karo

Jaisa humne pehle discuss kiya tha — DO NOTHING ke sath RETURNING sirf naye insert par row deta hai, conflict par khali reh jata hai (isi liye extra SELECT chahiye hoti thi). Lekin DO UPDATE (chahe woh no-op ho) ke sath, RETURNING hamesha row de deta hai — chahe naya insert ho ya conflict ho. Is se dono cases mein sirf ek hi round-trip lagta hai.

SQL:

```sql
INSERT INTO applications (job_id, applicant_id, screening_answers, profile_snapshot)
VALUES ($1, $2, $3, $4)
ON CONFLICT (job_id, applicant_id) DO UPDATE
  SET job_id = EXCLUDED.job_id  -- no-op: sets to same value, forces RETURNING to fire
RETURNING id, (xmax = 0) AS created;
```
